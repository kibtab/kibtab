# Kibtab v0.7.0

Released: Not released. Commit: none.

Version 0.7.0. This file holds the changes for the audit and locking release.

## Added

* `_kibtab_meta.audit_log` holds one audit row for each cell change.
* The instance stores the user, the time, the old value, and the new value.
* The instance reads the user from the `X-Kibtab-User` request header.
* The instance stores `unknown` for a write without the header.
* `SyncService` writes the audit rows in the transaction of the data write.
* `SyncService` advances the table version in that same transaction.
* The sync result holds the new version of each written row.
* `TableRegistry` holds `LockVersion`. It holds the version row until the
  transaction ends.
* `TableRegistry` holds `BumpVersion`. It advances the version by one.
* `RowRepository` holds `ReadRow`. It gives the old value of the cell.
* The route `GET /v1/tables/{table}/rows/{row}/audit?field=name` reads the
  audit rows of one cell.
* `ports.AuditReader` reads the audit rows of one cell.
* `domain.AuditRow` holds one audit row.
* The retention job removes the audit rows older than the retention days.
* `KIBTAB_AUDIT_RETENTION_DAYS` sets the retention days. The default is 90.
* `internal/adapters/driven/postgres/audit.go` supplies both audit ports.
* An index serves the audit query. A second index serves the retention job.
* A test writes a cell and it finds the audit row.
* A test sends a stale write and it finds no new audit row.

## Changed

* One transaction holds each port call of a write group. A context carries it.
* `RowRepository`, `TableRegistry`, and `AuditWriter` take a context.
* `TransactionRunner.Run` gives the transaction context to its function.
* `AuditWriter` moves from `Write` to `Record`. One audit row replaces the
  five arguments.
* A table with no version row reports version 1.
* `SyncService` advances the version for each written row group.
* The `version` field of a sync result holds the new version.

## Fixed

* The instance mounts the REST routes. A client reaches the write path.

## Security

None.

## Upgrade

1. Read the install guide before you install v0.7.0.
2. Keep your `DATABASE_URL` and your `KIBTAB_TABLES` value.
3. Start the instance once. The migration adds the `changed_by` column and
   the indexes.
4. Set `KIBTAB_AUDIT_RETENTION_DAYS` when you keep less than 90 days of
   audit rows.
5. Set the `X-Kibtab-User` header in your proxy. A write without it stores
   `unknown`.
6. Build the client with `make client-build`.

## Notes

The header is optional. A reverse proxy or a single sign-on layer sets it.

The retention job runs every 24 hours.

The export of an audit row is out of scope.
